Does your checkout tracking break on 26 August?

On 26 August 2026, Shopify stops running the code in Settings → Checkout → Additional scripts. Anything in that box stops firing. There is no error and no warning email — your conversion numbers just go flat, and most people find out weeks later when they wonder why ad performance collapsed.

This page tells you whether it affects you. It takes about a minute and you don't have to install anything.

Check your store in 60 seconds

Step 1

Open your Shopify admin and go to Settings → Checkout.

Step 2

Scroll to Order status page and find the Additional scripts box.

Step 3

Look at what's in it.

If the box is empty

You're fine. Nothing breaks on 26 August. You can stop reading.

If there's anything in it

Some or all of it stops working. What matters is what the code does — the table below tells you which parts you actually lose.

What to do about it

The fix is the same regardless of who does it: each tag has to be rebuilt as a Web Pixel, which is the sanctioned replacement Shopify wants you on. It runs in a sandbox, it survives the upgrade, and it keeps working.

Three routes, honestly:

  1. Do it yourself. If you have one GA4 tag and you're comfortable in the admin, this is genuinely a 30-minute job. Shopify's own docs on customer events cover it.
  2. Ask your developer. If someone built your store, send them this page. They'll know what to do with it.
  3. Use a tool. Several exist now, including ours. Worth it if you have several tags, or if you want a server-side copy as a backstop.

One thing worth knowing whichever route you take

Browser-based tracking misses orders even when it's set up correctly — ad blockers, closed tabs, flaky connections. A server-side copy sends the order from your store rather than the shopper's browser, so it arrives regardless. If both legs share one order ID, nothing gets counted twice.

That's the part most migration tools skip, and it's the part that still matters on 27 August.
